2. Satış iadesi (müşteri → firma)

2.1 İade irsaliyesi (fiziksel mal geri dönüşü)

Ekran İrsaliye Yönetimi · aksiyon: İade İrsaliyesi

API POST /delivery_notes/:id/iade · body: isteğe bağlı warehouse_id, miktarlar[{satırId}]

Kaynak irsaliye (Onaylı veya Faturaya Dönüştü) │ ▼ İade irsaliyesi (Taslak → Onaylı) source_document_type = SATIS_IADE │ ▼ Stok hareketi IADE_GIRIS (direction +1) belgeTipi = SATIS_IADE │ ▼ Depo bakiyesi artar (iade girişi)
  • Kaynak durum: yalnızca Onayli veya FaturayaDonustu.
  • Depo: body’deki warehouse_id veya kaynak irsaliye deposu.
  • Miktar: satır bazında kısmi iade desteklenir; verilmezse kaynak miktarın tamamı.
  • Yeni belge açıklaması: İade ← {kaynak_irsaliye_no}.

2.2 Satış iade faturası (mali ters kayıt)

Ekran Fatura Yönetimi → İade Faturası · ayrı liste: Satış İade Faturaları (invoice_type=Iade / SatisIade)

API POST /invoices/:id/iade

Kaynak satış faturası │ ▼ Yeni fatura: invoice_type = SatisIade tutarlar negatif (total / net / tax / payable) source_document_type = SATIS_IADE │ ▼ Durum: Taslak (muhasebe/onay süreci ayrı)
İade faturası stok hareketi üretmez. Fiziksel mal için önce (veya ayrıca) iade irsaliyesi gerekir. Tipik zincir: Sevk irsaliyesi → (iade irsaliyesi) → (iade faturası).

3. Satınalma iadesi (firma → tedarikçi)

3.1 Mal kabulden tedarikçiye iade (fiziksel çıkış)

Ekran Mal Kabuller · aksiyon: Tedarikçiye İade

API POST /mal-kabuller/:id/iade

Mal kabul (satırlar mevcut) │ ▼ Stok hareketi IADE_CIKIS (direction −1) belgeTipi = ALIS_IADE belgeId = mal_kabul_id │ ▼ Depo bakiyesi azalır (tedarikçiye çıkış)
  • Depo: body warehouse_id veya mal kabul deposu.
  • Kısmi miktar: miktarlar[{satırId}].
  • Yanıt: goods_receipt_id, stock_movement_id, movement_no.

3.2 Alış iade faturası

Ekran Alış İade Faturaları (invoice_type=AlisIade) · kaynak alış faturasından İade Faturası

API aynı uç: POST /invoices/:id/iade — kaynak tipinde “Alis” geçiyorsa AlisIade üretir.

Kaynak alış faturası │ ▼ Yeni fatura: invoice_type = AlisIade tutarlar negatif · source = ALIS_IADE │ ▼ Taslak iade faturası (mali)
Fiziksel iade (mal kabul → IADE_CIKIS) ile mali iade (AlisIade faturası) birbirinden ayrılmıştır. Her ikisi de aynı tedarikçi sürecinin parçasıdır; sırayla veya ihtiyaca göre kullanılır.

4. Fason iadesi (emanet → firma deposu)

Modül Fason Yönetimi · API POST /fason/siparisler/:id/iade

Fasoncuya sevk edilip kullanılmayan malzemenin geri alınmasıdır. Emnet deposundan çıkış + hedef firmaya giriş yapılır.

Fason sipariş │ ▼ Emanet depo (partner emanet) ──IADE_CIKIS──► çıkış │ ▼ Hedef depo (to_warehouse_id) ◄──IADE_GIRIS── giriş │ ▼ subcontract_returns kaydı (isteğe bağlı quarantine → stok_status = Kalitede)
  • Zorunlu: to_warehouse_id / warehouse_id, satır listesi (satirlar / lines).
  • Hareket kodu: FAS-IADE · belge tipi: FasonIade.
  • quarantine / qc_required true ise giriş stoğu Kalitede statüsünde açılır.
  • Açıklama / reason alanları desteklenir.

5. Kalite ile iade ilişkisi

Kalite modülü tek başına “iade belgesi” üretmez; karar kapısıdır.

  • GKK (giriş kalite): Mal kabul / fason teslimat sonrası ret → tedarikçiye iade veya yeniden sevk / hurda seçenekleri.
  • ÇKK (çıkış kalite): Üretim sonrası ret → yeniden işleme veya müşteriye sevk engeli.
  • Ret nedeni kalite emrine yazılır; fiziksel/mali iade ilgili satış veya satınalma iade uçlarıyla tamamlanır.
GKK/ÇKK emri → Ret │ ├── Satınalma tarafı → Mal kabul iadesi / Alış iade faturası ├── Satış tarafı → İade irsaliyesi / Satış iade faturası └── Fason tarafı → Fason malzeme iadesi (quarantine opsiyonu)

6. İK zimmet iadesi

Ekran İK İşe Alım / Zimmetler · aksiyon: İade Al

API POST /hr-ise-alim/zimmetler/:id/iade

  • Durum Zimmette → Iade; returned_at set edilir.
  • İşten çıkış onayında açık zimmet varsa engellenir (“önce iade edin”).
  • ERP stok kartına bağlı hareket üretmez; demirbaş zimmet kaydıdır.

9. Uçtan uca tipik senaryolar

A) Müşteri mal iade etti

  1. Satış irsaliyesini aç → İade İrsaliyesi (gerekirse kısmi miktar).
  2. Depoya giriş ve bakiye kontrolü.
  3. Gerekirse satış faturasından İade Faturası (mali kapanış).
  4. Liste: Satış İade Faturaları.

B) Tedarikçiye mal iade

  1. Mal kabulü aç → Tedarikçiye İade (stok çıkışı).
  2. Gerekirse alış faturasından iade faturası (AlisIade).
  3. Liste: Alış İade Faturaları.

C) Fasoncuya fazla sevk edilen malzeme geri

  1. Fason siparişte iade satırlarını ve hedef depoyu ver.
  2. Kaliteye düşecekse quarantine işaretle.
  3. Emanet bakiyesi ve firma depo bakiyesini doğrula.

D) Personel zimmet iadesi

  1. Zimmet kaydında İade Al.
  2. İşten çıkış öncesi açık zimmet kalmamalı.

10. Sınırlar ve dikkat noktaları

  • İade irsaliyesi yalnızca onaylı / faturaya dönüşmüş satış irsaliyesinden.
  • İade faturaları varsayılan Taslak; onay/muhasebe ayrı adımdır.
  • Satış iade faturası stok üretmez; stok için irsaliye iadesi şarttır.
  • Mal kabul iadesi ayrı bir “iade irsaliye belgesi” yerine doğrudan stok çıkışı üretir.
  • Firma kapsamı (X-Firma-Id) belge ve stok işlemlerinde geçerlidir.
  • Kalite ret’i otomatik iade belgesi açmaz; operatör ilgili iade aksiyonunu seçer.
